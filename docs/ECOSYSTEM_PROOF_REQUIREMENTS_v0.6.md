# Ecosystem v0.6 proof requirements

A review should reject the candidate if any of these are merely asserted rather than proven:

- exact candidate identity;
- mixed v0.1/v0.2 validation;
- active route generation;
- no-JavaScript/no-form surface;
- preserved security headers;
- canonical and sitemap coverage;
- Resource locator enforcement;
- absence of hidden endorsement language in the public contract.

Content freshness is a curation claim and requires the recorded first-party review trail plus future re-review, not a unit test alone.
